# Opt-in source structured-log collection

Current installation/credential/role commands: [independent release procedure](../../../hrms-documentation/docs/deployment/organization-infrastructure.md). Application consumers remain in svc; broker/Connect and database setup are independently owned.

[otel-filelog.template.yaml](../../../hrms-documentation/deploy/hrms/organization/otel-filelog.template.yaml) and [filelog.compose.template.yaml](../../../hrms-documentation/deploy/hrms/organization/filelog.compose.template.yaml) close the stdout ingestion path. This is diagnostics, not retained business/security history. The pinned official **contrib** collector0.162.0 includes filelog and transform; the main core collector does not. The image digest was verified against the official GHCR manifest.

Deploy one collector per explicitly approved source service/company binding on its source host. Set the service's existing `KABIPAY_LOG_FORMAT=json` before collection. Map exactly that container's Docker JSON log file read-only to `/var/log/kabipay/approved-service.json.log`; do not mount the Docker socket, all container logs, `/var/log` wholesale or another company's log. Operator must verify the source container ID, exact absolute file, service name and company UUID together. Set `SOURCE_SERVICE_NAME` and `SOURCE_TENANT_ID` from reviewed deployment metadata; they are never inferred from a log's tenant/org/user fields. Bind the exporter certificate/identity to that deployment and route the backend dataset from these trusted static resource attributes plus certificate identity, not arbitrary JSON claims. Metadata/control-plane services use a separately documented control-plane deployment binding, not a fabricated company UUID.

The receiver parses the Docker wrapper/time, then the structured Rust JSON. Malformed wrappers/application records are quietly dropped as diagnostics (monitor counts), not exported raw. The transform replaces body with `RUST_STRUCTURED_LOG`, keeps only enum severity and a small exact diagnostic-code allowlist, and removes all log-supplied attributes. It does not retain arbitrary message/error/span/body/token/password/Authorization/employee/user/tenant/org fields. Unknown codes become generic records; extend the static allowlist only after reviewing the emitting caller. It never turns business bodies into searchable logs.

State is bounded in persisted file offsets and exporter queues under explicit `SOURCE_FILELOG_STATE`; read access to the approved log and write access to this state directory must be granted to the collector UID without adding the collector to Docker administration. Export uses private mTLS, bounded memory/queue/retry and no new host port. Keep diagnostics retention short (default30days in the backend), separate from seven-year business history, with separate principals and operator queries. This reference does not deploy the backend or prove its retention/authorization policy.

An exact file bind can remain attached to an old inode after Docker log rotation or container recreation. Rotation/container lifecycle must update the reviewed file binding and restart/remount the collector; monitor file age/offset stagnation and dropped/oversized/malformed records. Do not silently broaden the mount to follow arbitrary containers. Source Docker JSON logs must also have bounded `max-size`/`max-file`. Default `start_at:end` avoids automatically exporting old logs; a historical diagnostic import is a separate reviewed task. This path is best-effort diagnostics, not an audit receipt guarantee.

Validation uses the pinned collector `validate --config=...`; actual synthetic ingestion runs `ORGANIZATION_SYNTHETIC_ACCEPTANCE=true node test/filelog-acceptance.mjs` from the Node package. The latter mounts only newly generated synthetic Docker/Rust JSON, runs without networking, checks that secrets/private bodies/forged tenant claims disappear and trusted service/company metadata remains, then removes only its own container/state directory. Production log binding, exporter mTLS, backend routing and retention remain deployment acceptance requirements.

Primary references: [filelog0.162.0](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/v0.162.0/receiver/filelogreceiver/README.md), [transform0.162.0](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/v0.162.0/processor/transformprocessor/README.md).
