## Suspension, resume and legacy checkpoint recovery

Historical business delivery acknowledges successful handling as READY without changing current inbox state; history/reporting must still finish their own sink writes. READY is only a role delivery checkpoint. Current access and capture health additionally require live current installed membership, explicit accepted source bootstrap, exact marker epoch, source freshness and every role/partition barrier. Successful historical delivery never clears an existing PARTIAL/QUARANTINED fault.

The coordinator first classifies the exact source membership ID/version under fixed source provenance. A recognized suspended/detached or older-epoch raw marker is terminally acknowledged without Connect access, marker registration or barrier publication; a retired connector cannot block it. Unknown IDs/future epochs and invalid raw provenance enter durable metadata-only quarantine before Kafka offset commit, also without Connect. Only ACTIVE registration requires persisted Connect confirmation: policy locks are released during that I/O, then exact membership/epoch is revalidated under fresh locks. Unavailable policy, missing active Connect proof or unavailable quarantine retry. A registered barrier already queued on a company topic also acknowledges historically without current capture writes. Provision the coordinator quarantine-topic WRITE ACL as well as its source READ and barrier WRITE ACLs. Its inherited `KAFKA_QUARANTINE_TOPIC` is mandatory.

Old releases wrote successful history as `PARTIAL/HISTORICAL_MEMBERSHIP`, and their merge could mask a subsequent invalid PARTIAL code. There is deliberately no automatic reset of those legacy rows. The administrator-only `kabipay_ops.organization_reconcile_historical_checkpoint(role,org,company,topic,partition,expected_offset,expected_ack,current_marker,review_sha256,accepted_by)` recovers only that exact legacy state. First review durable quarantine and source/sink reconciliation through the exact role/topic/partition offset; resolve any real data gap and retain an immutable review manifest. Pass its SHA256 and an existing principal ID. Read `acknowledged_at::text` to preserve PostgreSQL microseconds in the exact fence. Pause the affected role briefly if deliveries keep invalidating the reviewed checkpoint.

The function requires a fresh latest source marker for the accepted current epoch, source bootstrap completion and every role/partition barrier with its covering delivery offset. It locks live policy plus the exact checkpoint, rejects stale offset/timestamp, genuine invalid PARTIAL and every QUARANTINED row, and atomically retains `organization_checkpoint_reconciliation` before clearing only the historical code. Other unresolved faults keep health false. Workers and ordinary application roles receive no reconciliation EXECUTE or receipt mutation privileges; grant this function only to an explicitly accepted operator identity. No existing production checkpoint has been reset.

## Source-owned export and backfill

Run `npm run source:export` only at a fixed company deployment. Required settings: `SOURCE_COMPANY_DATABASE_URL`, `SOURCE_DATABASE_NAME`, `SOURCE_SCHEMA`, `SOURCE_TENANT_ID`, `SOURCE_ORGANIZATION_ID`, `SOURCE_EXPORT_ID`, `SOURCE_EXPORT_KIND=OUTBOX|LEGACY_AUDIT`, `SOURCE_COMPANY_TOPIC`, `SOURCE_EXPORT_DIRECTORY`, Kafka broker/client TLS settings and source PostgreSQL CA. `SOURCE_EXPORT_MAX_CHUNKS` defaults1, maximum20; each chunk has at most200rows.

The source validates its own database/membership, locks a committed cutoff, stores immutable byte/hash/range manifests, and resumes existing chunks. Broker ACK precedes the source publication checkpoint. Uncertain ACK replay keeps original event IDs. General consumers still receive no source credentials. Genuine audit mapping exports source IDs/user/time, closed entity/action/status metadata and original-row SHA256. Private before/after/IP/user-agent data stays at the source backup boundary. Unknown labels/earlier intervals remain explicit gaps; current metric snapshots do not reconstruct missing actions.

Accept a historical range only after verifying every contiguous chunk/hash and sink coverage. A finished source job or one observed Kafka event alone cannot expand central accepted `history_from`. Operator source backup/restore remains necessary for private legacy bodies that are purposefully excluded from organization topics.

## Protected archive service

`npm run start:archive` serves only POST `/v1/archive/export` and `/v1/archive/retrieve`. Require mTLS plus public-only `KABIPAY_SERVICE_TRUST_KEYS` using the existing RS256 service contract: issuer `kabipay-internal-service`, type `hrms-service+jwt`, service `kabipay-organization`, audience `kabipay-organization-archive`, exact tenant/method/route/body hash and lifetime<=60seconds. Bind tenant/org allowlists with `ARCHIVE_BINDINGS_FILE`. Root central configuration is `KABIPAY_ORGANIZATION_ARCHIVE_URL`; root checks current exact history/export ALL before and after the call.

Sidecar configuration: archive-only metadata URL/CA; fixed CH read credentials/CA; `ORGANIZATION_ARCHIVE_ROOT`, `ORGANIZATION_ARCHIVE_KEY_FILE` (32raw bytes), `ORGANIZATION_ARCHIVE_KEY_VERSION`, archive TLS server/client-CA files. Central HTTPS client configuration is `KABIPAY_ORGANIZATION_ARCHIVE_CA_FILE`, `KABIPAY_ORGANIZATION_ARCHIVE_CLIENT_CERT_FILE` and `KABIPAY_ORGANIZATION_ARCHIVE_CLIENT_KEY_FILE`; HTTPS requires the client certificate/key pair. Optional `ORGANIZATION_ARCHIVE_READ_KEYS` maps old encryption key versions to protected sidecar files. Root/source services receive public service trust material, never this encryption key.

Export requests contain archive UUID, fixed scope/member epoch, source `from`/`through`, and actor IDs. Sidecar independently requires accepted history_from and a fully acknowledged source capture-through. It rejects >10000events/16MiB plaintext, unavailable exact source envelopes and mismatched ranges. It preserves source timestamp precision, original whitelisted bodies and actor attribution. Existing staging rows missing `source_event` require verified source replay; do not fabricate an envelope. AES256GCM authenticates exact manifest/count/IDs/per-event/range/plaintext/ciphertext hashes. Files are synchronized and atomically published without overwrite. A PG advisory transaction serializes archive IDs; authentic orphan files can be verified/re-registered after uncertain database writes before querying a newer snapshot.

Retrieval uses immutable manifest membership version and recognizes the same historical member ID; safe resume does not invalidate existing authenticated bytes. Current central authorization remains mandatory. UUID-only protected paths, no caller URL/path/key, and damage/wrong scope/key/epoch checks fail closed. Archive access audit is committed with metadata registration. Rehearse key custody, storage durability and off-host restore on the target Linux/filesystem deployment; Windows synthetic file tests are not a power-loss drill.

## Retention execution

ClickHouse business/reporting/control history TTL deletion is explicitly disabled (`DELETE WHERE 0`). Outbox retention does not authorize history deletion.

`npm run cleanup:outbox` defaults dry-run. Bind `SOURCE_OUTBOX_DATABASE_URL`, fixed source CA, metadata evidence URL/CA and `RETENTION_REQUEST_FILE`. Execute only with trusted `RETENTION_OPERATOR_CONFIG_FILE` (`enableExecute`, accepted policy UUID/version, exact database/scope binding) and explicit `RETENTION_EXECUTE=true`. The persisted policy defaults PENDING/disabled and requires exact source/schema/database, minimum age, <=100batch, restore proof, acceptance and expiry. Evidence binds exact candidate IDs/hashes, source range, restore digest, cutover and lease. Source candidate locks and final capture/expiry checks precede deletion; an immutable source cleanup receipt commits in the SAME transaction. No business/audit/command receipt table is targeted.

Control cleanup additionally requires fixed `CONTROL_BINDING_FILE`, operator-only CH credentials (`CONTROL_RETENTION_CLICKHOUSE_*`), exact retained control ID/content hashes and a READY checkpoint covering the cutover offsets. This includes protected NULL-org identity history without granting it to organization applications. Safe equivalent UTC timestamp formatting is checked against the original retained SHA256 without weakening any other field.

Tests use `requireSyntheticFixture=true` plus generated database/nonce proof. No production retention execution has occurred. Provision source SQL lock/DELETE and cleanup-receipt INSERT privileges only to the accepted operator deployment after backup/restore/cutover review. Keep consumer credentials and organization app roles free of DELETE/retention-policy write permission.
